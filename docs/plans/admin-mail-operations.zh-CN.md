# Zmail 平台运营总看板 · 业务设计

评审稿，2026-11-18。本期使用者是平台管理者。日常使用从“今天发了多少”进入“哪个组织发的”，最后能核对某封实际外发邮件。组织员工继续使用现有客户控制台。

## 首版模块

| 模块 | 页面提供的信息 | 点击后的业务结果 |
|---|---|---|
| 平台概览 | 组织总数、各组织成员去重后的总人数、选定日期已发与失败数、过去七天每日趋势 | 点某天查看当日各组织发送量；选择零发送的日期也能看到全部组织 |
| 组织与成员 | 支持按名称搜索；每行显示组织名、成员数、邮箱数、当日已发和失败数 | 成员数打开现有成员列表，展示角色和加入时间；点击发信量进入该组织当日流水 |
| 发信流水与内容 | 日期、组织、邮箱、状态过滤；显示发送时间、发件地址、主题、状态、投递回执 | 点击一封，在有内容权限时展示当时发送的正文快照；普通列表不预加载正文 |
| 内容访问审计 | 记录谁、何时、以什么理由查看哪个组织的哪封邮件 | 支持按组织、查看人和时间追溯；审计记录不复制正文、验证码或收件人地址 |

新模块复用已有 Admin 组织列表、成员分页和审计界面。平台总览与跨组织外发流水是新增功能；部署现有 Admin 静态页面本身不能产生这两种数据。

## 统计口径

- 组织数包含零发送、零邮箱的现存组织。员工数以有效组织成员关系计，包含所有者、管理员和成员，剔除已删除用户；界面区分停用账号。一个人在两个组织中分别计一人，全平台人数去重。邮箱数单列。
- 每日已发采用与现有邮件统计一致的记录创建日和状态，范围为 UTC 00:00 至次日 00:00；页面标注 UTC。每条出站消息只计一次；测试邮件和广播产生的实际消息也计入。入站信、待发广播收件人、尚未产生消息记录的系统通知不计入。
- 已发、失败、排队分列；已投递、退信、投诉来自事件，两种口径分别展示。重复回执不能增加发送量。仅展示实际存留的历史，已删除内容不从日志恢复。
- 首屏默认今天与七日趋势；限定区间最多 31 天。组织列表按已发量降序、组织 ID 排序，流水按创建时间、消息 ID 逆序，每页 20 条。页面明确区分无数据、加载失败和权限不足。

## 权限和上线边界

使用独立 Admin 会话，每次请求校验有效的平台授权。组织 owner/admin 不自动获得跨组织统计权限。额外的内容查阅授权默认关闭；查看动作须填写原因，审计写入成功才能返回正文。首版仅展示外发纯文本，HTML-only 邮件转换为可读文本，不加载远程图片、执行脚本或提供附件下载。私信收件箱、登录验证码和账号恢复邮件不纳入平台巡查页面。实现时需核实可识别的敏感邮件类别；无法可靠分类时，默认仅开放可确认的组织广播正文，其他正文走显式组织授权。

现有 operator grant 同时支持账号停用、撤销会话等管理操作。上线应把统计查看与账号管理分权；既有组织账号不能因需要看数字而自动获得完整 operator grant。首次授权的具体人员须由所有者指定。跨组织正文不进入浏览器持久缓存或普通应用日志。

## 数据和实现顺序

1. 平台 API 提供概览、按组织按天统计。组织与成员关系来自组织模块，外发总数来自邮箱模块；分别聚合后再关联，避免一个组织三个员工把四封邮件放大成十二封。组织详情复用已有成员接口并校验授权。
2. 增加平台外发分页查询、带原因的内容查阅及审计。API 同时以组织 ID 和消息 ID 定位资源，校验出站方向和内容权限。清空筛选、分页、退回组织页应保留选定日期。
3. 发布独立 Admin 静态端和同源会话网关。先在两组织测试数据上核对，再启用生产授权、发布页面，以只读查询和现有组织控制台对账。异常时关闭新入口及后台读接口，原广播队列和用户登录保持可用。

## 验收样例

| 场景 | 必须观察到的结果 |
|---|---|
| 两组织分别有两名和三名成员，一人跨组织 | 组织数 2，各组织 2、3，全平台去重 4 |
| 一组织在同一天有 2 封成功、1 封失败、1 封收信，另一组织零发送 | 总览已发 2、失败 1，点开已发得到同样两封，组织列表保留零发送行 |
| 同一封邮件收到两次 delivered，且模板在发送后被修改 | 发信量不变；详情显示已发送版本 |
| 普通成员、组织所有者、仅有看板权限者直接访问正文 URL | 未获授权均不可读；有权查看者留下审计，撤权后下一次读取失败 |
| UTC 午夜前后各一封，或 API 不可用 | 两天分别计数；故障显示异常与重试，不能显示假零 |
| 生产验收 | 用获授权账号登录、观察真实组织数与成员数、选某天从总量点到原信，普通组织会话无法打开同一内容 |

## 后续候选

优先增加“异常与额度”模块，揭示长时间排队、额度用尽、退信和投诉突增，支持跳回原广播处理。其次增加“域名与绑定健康”，集中显示域名验证、来信路由和未来外部邮箱授权到期。需求成立后再规划通知、计费及导出；它们无需阻塞首版查询。

上线前的业务决定：指定初始平台查阅人，并明确其正文读取范围（仅组织广播或含普通业务外发）。这决定授权和审计验收，不影响聚合指标定义。
