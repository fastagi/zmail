# 组织里的“开发者”授权（设计稿，待老板审）

状态：草稿 · 2026-11-23 · 方案 A（成员 + “开发者”授权），老板已选定

## 1. 为什么要做

公司自己的工程师要把公司的系统（注册验证码、订单通知、告警、工单回复等）接进公司的 Zmail。今天只有两条路，都不合适：

- 把工程师设成**管理员**：能接入了，但同时能管成员、改域名、看全组织设置，权限太大。
- 让他当**普通成员**并给 “API” 授权：只能用自己的邮箱发信，碰不到事务邮件模板、Webhook、退信名单、用量这些接入必需的东西（这些今天只有所有者/管理员能用）。

目标：管理员给某个成员打开一个“开发者”开关，他就能完成整个接入，而且看不到同事的邮件、管不了组织。

## 2. 竞品怎么做（结论）

- Google Workspace / Microsoft 365：接入走“管理员创建应用 + 服务账号 / 应用权限”，没有“开发者”角色，粒度粗，管理员负担重。
- 飞书邮箱 / 腾讯企业邮：开放平台的应用由管理员审批，开发者在开放平台单独有身份。
- Resend / Postmark：团队成员有 Developer（或类似）角色，能管 API Key、Webhook、模板、看日志，不能管账单和成员。

取舍：Zmail 已有“按人授权”的体系（群发、联系人、模板、API、客户端），把“开发者”做成其中一项，管理员最容易理解，不新增角色。

## 3. 开发者能做什么 / 不能做什么

打开“开发者”授权的成员，在本组织内：

| 能力 | 今天谁能用 | 开发者授权后 |
|---|---|---|
| 开发者控制台（快速开始、发送日志、限额页） | 所有成员可进，但多数操作被拒 | 全部可用 |
| API Key（含 `mail:transactional` 范围） | 需 “API” 授权 | 自动包含，无需另开 “API” |
| 事务邮件模板 新建/修改/删除 | 所有者/管理员 | 可以，但发件地址只能用分配给他的域名（见 4） |
| Webhook 新建/修改/删除/查看投递 | 所有者/管理员 | 可以，只能管自己建的 Webhook；管理员能看到并管理全部 |
| 退信/拒收名单 查看、移除 | 所有者/管理员 | 可以查看和移除；不能批量导入 |
| 事务邮件与 API 发信的用量、限额 | 所有者/管理员 | 只读 |
| 发送日志 | 所有成员 | 不变 |

开发者**不能**：看同事邮箱或共享邮箱（除非另被共享）、添加或移除成员、改成员授权、接入或删除域名、改组织设置、发群发（群发仍是单独授权）。

## 4. 发件范围：管理员给开发者划定能用的域名

一个组织可能有多个域名（例：fast-ui.com 是对外品牌，shu.ie 是内部系统）。管理员打开开发者授权时，选择他能用来发信的域名（默认：组织的默认域名；可多选；也可选“全部已验证域名”）。

这个范围在三处生效：

1. 新建/修改事务邮件模板时，发件地址必须落在范围内，否则拒绝（错误码 `DEVELOPER.DOMAIN_NOT_ALLOWED`）。
2. 开发者新建的 API Key 自动绑定本组织，`sending_domains` 只能是范围的子集（复用 #223 的限定 Key 能力）；超出范围拒绝。
3. 管理员缩小范围后，已有的 Key 和模板在发信时按新范围检查，超出的发信被拒，模板列表里标出“发件域名已不在你的范围内”。

## 5. 管理员怎么操作

- 组织 → 成员：每个成员的授权里多一项“开发者”，打开时弹出“允许使用的发件域名”多选。
- 邀请成员、花名册导入：授权选项里同样有“开发者”（花名册列 `developer=yes`，域名默认组织默认域名）。
- 成员列表的授权标签里显示“开发者 · fast-ui.com”。
- 关掉开发者授权：他的 Key 立即不能再发事务邮件（Key 不删除，管理员可在 API Key 页看到并吊销）；他建的 Webhook 和模板保留，归属不变，管理员可接管。

## 6. 开发者看到什么

- 侧栏“开发者”入口对他亮起；控制台首页的快速开始直接给出：已绑本组织、只含他能用的域名的示例（和 #223 的示例同一套）。
- 没有授权的普通成员进控制台，看到“需要管理员开通开发者授权”的说明和“联系管理员”提示，而不是一堆 403。

## 7. 以后的口子：系统地址收信（这次不做）

以后开发者可以申请“系统地址”（如 `support@`、`orders@`），收到的信通过 Webhook 推给程序，而不是进某个人的邮箱。这次只做发信，但为它留好：

- 发件范围先按“域名”存，表结构允许以后存“具体地址”。
- Webhook 事件目录里预留 `message.received` 类事件，这次不实现。

## 8. 非目标

- 不新增“开发者”角色；不改所有者/管理员/成员三种角色。
- 不做 OAuth 应用 / 第三方应用市场。
- 不做系统地址收信。
- 不改群发授权。

## 9. 验收标准

1. 管理员给成员 A 打开开发者授权、范围 fast-ui.com：A 能建 API Key（自动绑定本组织、只含 fast-ui.com），能建发件地址为 `no-reply@fast-ui.com` 的事务模板，用 Key 调事务发信接口成功。
2. A 建发件地址为 `x@shu.ie` 的模板被拒（`DEVELOPER.DOMAIN_NOT_ALLOWED`），建含 shu.ie 的 Key 被拒。
3. A 能建、改、删自己的 Webhook，能看到投递记录；不能改管理员建的 Webhook。
4. A 能查看、移除退信名单条目；能看用量和限额。
5. A 打开成员管理、域名管理接口一律 403；看不到同事邮件。
6. 关掉 A 的授权后，A 的 Key 发事务邮件被拒，Webhook 和模板仍在、管理员能管理。
7. 没有授权的成员 B 进开发者控制台看到开通说明，不出现原始 403 提示。
8. 花名册导入 `developer=yes` 的行，成员加入后即带开发者授权。
9. 本地真实走一遍以上流程并加入 `replay-local.py`；生产复验用 fast-ui.com。

## 11. 审阅后定下的细节

### 待老板确认（我的推荐写在前面，老板同意就按这个做）

1. **发件范围挂在“谁在发”上**：每次发信，按发信 Key 的创建者“当下”的身份检查实际发件地址。管理员建的 Key 不受任何开发者范围限制；开发者的 Key 调用发件域名不在他范围内的模板（不管模板是谁建的），一律拒绝（`DEVELOPER.DOMAIN_NOT_ALLOWED`）。这样不用把范围复制进 Key，管理员缩小范围立刻生效。
2. **事务模板按域名管，不按创建者管**：开发者能改、删发件域名在他范围内的所有模板；范围外的模板只读。模板不加创建者字段。Webhook 仍按“谁建的谁管”，因为 Webhook 有接收地址和密钥，属于个人接入。
3. **“全部已验证域名”动态跟随**：以后新验证的域名自动进入范围。Zmail 平台共享的发信域名不算在范围内。
4. **开发者的 Webhook 只收“程序发出的信”的事件**：只收事务邮件和 API 发信产生的事件（投递、退信、投诉），而且限于他范围内的域名。同事从邮箱里手写发出的信，相关事件不推给开发者的 Webhook。这是“看不到同事邮件”在 Webhook 上的边界。管理员建的 Webhook 不变。

### 我自己定的（小问题）

- 所有者和管理员自动拥有全部开发者能力，不受范围限制（沿用 `EffectiveFeatures` 惯例）。
- 数据形状：单独建表 `member_developer_grants`（成员、组织、全部域名开关、域名列表），以后可加“具体地址”。`MemberFeatures` 里的 `Developer` 布尔值由这张表推导，`Has`/`requireFeature` 照旧可用。
- 退信名单移除不按域名限制（名单本身没有域名维度），每次移除都写审计日志，记录是谁移除的。
- 用量和限额显示全组织数字，只读；开发者不能调整限额。
- 开发者授权“包含”API 授权：关掉开发者授权后，如果管理员另外单独开过 API 授权，这项保留，他的 Key 仍可做普通发信，但不能再发事务邮件，也不能管理模板和 Webhook。
